# 夢の記録（Dream Recorder）

iPhoneで、夜中に見た夢を「ボタン1回押す→話す→もう1回押す→振動を確認して眠る」だけで録音・保存できるアプリです。React Native（Expo）で作られたネイティブアプリで、ExpoGoではなく **Development Build**（自分専用のカスタムアプリ）として動かすことを前提にしています。

このドキュメントは、開発経験が少ない方でも迷わず動かせることを目指して書いています。長いですが、初期設定は最初の1回だけです。

## 1. この方式（Expo / React Native）を選んだ理由

夜中に「ボタンを押す→話す→もう一度押す→眠る」という体験を、**確実に**成立させるには、以下がすべて必要です。

- 画面をロックしていても（あるいは画面ロック寸前でも）録音が止まらない
- Safariやアプリを完全に終了しても、録音した件数と音声が消えない
- 保存できたことを「振動」で確実に伝えられる
- オフラインでも完全に動作する

これらはSafari（PWA/Webアプリ）だけでは**構造的に保証できません**（理由は次の章）。そのため、本アプリは **Expo（React Native）のネイティブアプリ**として実装しています。

- **Expo Router**: 夜間画面・朝用画面の2画面をシンプルに管理
- **expo-audio**（非推奨の `expo-av` は不使用）: 録音
- **expo-sqlite**: 録音メタデータ・セッション履歴の永続化（正本データ）
- **expo-file-system**: 音声ファイルをアプリの Documents ディレクトリへ永続保存
- **expo-haptics**: 開始・保存・エラーの振動フィードバック
- **expo-keep-awake**: 録音中だけ画面スリープを防止
- **expo-crypto**: `randomUUID()` でID生成（RNには標準の`crypto`が無いため）

## 2. Safari版の制約（なぜWeb版だけでは作らなかったか）

このリポジトリには、今回新規に作成したExpo版**以外のSafari/Web版は存在していませんでした**（調査済み。既存コードはこのアプリとは無関係な別プロジェクトのみでした）。もしSafari版を検討する場合、以下の制約が実機で必ず問題になります。

| 課題 | Safari(PWA)での実態 |
|---|---|
| 画面ロック中の録音継続 | iOSのSafariは画面ロック・バックグラウンドで`MediaRecorder`が停止することがある |
| Safari終了後もデータが残る | `localStorage`は消えにくいが保証はなく、`IndexedDB`もiOSでは低ストレージ時に消去されることがある。**「Safariを閉じても必ず残る」とは主張できない** |
| 確実な振動 | Web Vibration APIはiOS Safariで**利用不可**（無視される） |
| ファイルとしての永続音声 | Web File System Access APIはiOS Safariで利用不可。Blobをメモリ/IndexedDBに置くしかなく、大容量・長時間録音での信頼性が低い |
| ホーム画面起動後の安定動作 | 「ホーム画面に追加」したPWAも内部はSafariで、上記制約は変わらない |

**結論**: Safari版は「試作・デモ」までは作れますが、本要件（保存が絶対に消えない・振動で確実に伝える・画面ロック耐性）を満たせないため、**今回は実装していません**。もし将来Safari版を維持する場合は、上記制約をREADMEに明記した上で「補助手段」として位置づけてください。

## 3. Expo GoとDevelopment Buildの違い

- **Expo Go**: Appストアにある汎用アプリ。QRコードを読むだけで試せますが、**ネイティブコードを追加したパッケージは動きません**。今回使っている `expo-sqlite`・`expo-speech-recognition`（オンデバイス文字起こし）・バックグラウンド録音などはExpo Goでは正しく動作しない、または全く使えません。
- **Development Build**: このアプリ専用に作った、あなたのiPhoneにインストールする「自分だけのアプリ」。見た目はExpo Goに似ていますが、必要なネイティブ機能がすべて含まれています。**本アプリは必ずDevelopment Build（または本番ビルド）で動作確認してください。**

## 4. Windows PCしかない場合の手順

Windows PCでも開発は可能です。iPhone実機用のビルド（.ipa作成）だけは、Appleの制約上Mac環境が必要ですが、**EAS Build**というクラウドサービスを使えばMacなしでビルドできます。

1. [Node.js](https://nodejs.org/) LTS版をインストール
2. このリポジトリを取得し、`apps/dream-recorder` フォルダで以下を実行

   ```
   npm install
   npx expo install
   ```
3. Expoアカウントを作成（無料）: https://expo.dev/signup
4. EAS CLIをインストールしてログイン

   ```
   npm install -g eas-cli
   eas login
   ```
5. 以降は [5章](#5-macなしでeas-buildを使ってiphoneへ入れる手順) の手順でクラウドビルドします。

## 5. MacなしでEAS Buildを使ってiPhoneへ入れる手順

1. `apps/dream-recorder` フォルダで初回設定

   ```
   eas build:configure
   ```
   → iOSを選択。`eas.json` が自動生成されます（未生成の場合は下記例を参照）。

2. Development Build（実機に自分でインストールして試すための版）を作成

   ```
   eas build --platform ios --profile development
   ```
   - 初回は「Appleアカウントでの登録」または「アドホック証明書の作成」を聞かれます。画面の指示に従ってください（Apple IDでのサインインが必要です）。
   - ビルドはExpoのクラウドで行われるため、Macは不要です。数分〜数十分かかります。
3. ビルド完了後に表示されるURL、またはExpoダッシュボード（https://expo.dev ）からインストール用QRコードを取得
4. iPhoneのカメラでQRコードを読み取り、指示に従ってインストール

`eas.json` の例（無い場合は作成してください）:

```json
{
  "cli": { "version": ">= 13.0.0" },
  "build": {
    "development": {
      "developmentClient": true,
      "distribution": "internal",
      "ios": { "simulator": false }
    },
    "preview": {
      "distribution": "internal"
    },
    "production": {}
  }
}
```

初回インストール後は、`npx expo start --dev-client` を実行しているPCと同じWi-Fiに繋いだ状態でiPhoneからアプリを開けば、コード変更を毎回クラウドビルドし直さずに試せます（JavaScript側の変更のみ即時反映。ネイティブ設定を変えたときだけ再ビルドが必要）。

## 6. Apple Developer Programが必要になる条件と料金

- **Development Build（自分のiPhone1台〜数台で試すだけ）**: 無料のApple IDだけでも `eas build` は可能ですが、**7日ごとに証明書の再インストールが必要**になる場合があります（無料アカウントの制限）。
- **Apple Developer Program（年間 $99）が必要になるケース**:
  - 証明書の有効期限を気にせず使いたい場合
  - 家族・複数人のiPhoneに配布したい場合（Ad Hoc配布は端末登録が必要）
  - 将来 App Store 経由での配布・TestFlightでの配布を行う場合
- 個人が自分のiPhone1台だけで、多少の再インストールの手間を許容するなら、**無料のApple IDのみでも運用可能**です。

## 7. iPhoneへのインストール

- EAS Buildで作った `.ipa` / インストールリンクを、iPhoneの **Safari** で開いてインストールします（他のブラウザでは正しく動作しないことがあります）。
- インストール後、初回起動時に「信頼されていないデベロッパ」の警告が出た場合:
  設定 → 一般 → VPNとデバイス管理 → 対象のプロファイルを選択 → 「信頼」

## 8. ホーム画面から起動する方法

Development Build / 本番ビルドは通常のネイティブアプリとしてインストールされるため、**インストール直後からホーム画面にアイコンが表示されます**（Safariの「ホーム画面に追加」のような追加作業は不要です）。アイコンをタップするだけで起動します。

## 9. マイク権限について

- 初回、赤いボタンを最初に押したときだけ、画面上部に「初回のみ：ボタンを押すとマイクへのアクセス許可を確認します」という薄い案内が表示されます。
- その後iOS標準のマイク許可ダイアログが出るので「許可」を選んでください。
- 一度許可すれば、**次回以降は毎回確認されません**。
- 誤って「許可しない」を選んでしまった場合は、設定アプリ →「夢の記録」→ マイクのスイッチをオンにしてください。

## 10. 振動（Haptics）の確認方法

- **開始成功時**: 短い振動が1回（マナーモードでも振動は鳴ります。ただし「消音スイッチ」ではなく「システムの触覚設定」がオフだと鳴らない端末があります）
- **保存完全成功時**: 短い振動が一定間隔で2回
- **失敗時**: 成功とは明確に異なる「エラー」の振動パターン
- 設定アプリ → サウンドと触覚 → システムの触覚 がオンになっているか確認してください。

## 11. オフライン試験

1. iPhoneを機内モードにする（Wi-Fi・モバイル通信ともオフ）
2. アプリを起動し、録音→保存を実施
3. 保存完了の振動が鳴ること、朝用画面で件数・音声が確認できることをチェック

本アプリは録音・保存・振動・履歴表示のすべてが**完全にオフラインで動作**するように作られています（文字起こしのオンデバイス機能もネットワーク不要です。サーバーAPIを設定している場合のみ、その部分だけオンライン時に動作します）。

## 12. 録音データの保存場所

- 音声ファイル: アプリの **Documents ディレクトリ** 内 `dream-recordings/` フォルダ（`expo-file-system` の `Paths.document` 配下）。iOSの通常バックアップ対象領域内にあり、システムの「空き容量不足時の自動削除」対象にはなりません（キャッシュ領域は使っていません）。
- メタデータ（録音時刻・長さ・文字起こし・状態など）: アプリ内の **SQLiteデータベース**（`dream_recorder.db`）。
- どちらもアプリを削除すると一緒に削除されます。**アプリを削除する前に「13. バックアップ方法」を確認してください。**

## 13. バックアップ方法

- **iCloudバックアップ / iTunesバックアップ**でiPhone全体をバックアップしていれば、アプリのDocuments領域も対象に含まれます（標準のiOSバックアップの仕組み）。
- 個別の音声ファイルだけ取り出したい場合は、朝用画面の「再生」で該当の夢を確認しながら、必要な文字起こしテキストは「GPT貼り付け用文章をコピー」でクリップボードにコピーし、メモアプリなどへ貼り付けて保存してください。
- より高度なバックアップ（ファイル単位でのエクスポート）は、次の拡張候補です（本バージョンでは未実装）: Files.appでのアプリ書類共有を有効化する、あるいは共有シートから音声ファイルを送信する機能の追加。

## 14. APIを使わずに利用できる範囲

**録音・保存・履歴・振動・オフライン動作はすべてAPI（インターネット接続やOpenAI等の外部サービス）なしで完結します。**

APIが無くても使える機能:
- 録音の開始・終了
- 永続保存（SQLite + ファイル）
- 件数表示・履歴の復元
- 振動フィードバック
- 音声の再生
- 昨夜分の確定
- すべての耐久性要件（アプリ終了・再起動・オフライン等）

API/ネットワークが必要になるのは、**あなたが明示的に設定した場合の「サーバーAPIによる文字起こし」機能だけ**です。設定しなければ、その機能は単に「未処理」のまま音声が保持されます（失敗にはなりません）。

## 15. 文字起こしの方法と制約

優先順位に従って、実装可能な方式のみを採用しています。

### ① iOSオンデバイスSpeech framework（第一候補・実装済み）

`expo-speech-recognition`（Apple の `SFSpeechRecognizer` をラップするネイティブモジュール）を使い、`requiresOnDeviceRecognition: true` で**完全オフライン**の文字起こしを行います。

- **必須条件**: Development Build（Expo Goでは動作しません。ネイティブコードを含むためです）
- **日本語対応**: `ja-JP` を指定していますが、**日本語のオンデバイス音声認識モデルが端末にダウンロード済みである必要があります**。未ダウンロードの端末では失敗し、その場合は②へフォールバックします（②も未設定なら「未処理」のまま保持）。
  - モデルの確認/ダウンロード導線はiOSのバージョンによって異なります（設定 → 一般 → キーボード → 音声入力 など）。事前に確認してください。
- **権限**: マイク権限に加えて「音声認識」権限が必要です（初回のみダイアログ表示）。
- **対応端末**: `SFSpeechRecognizer` はiOS 10以降で利用可能ですが、日本語のオンデバイス認識対応状況は端末・OSバージョンに依存します。
- **オフライン可否**: 完全にオフラインで動作します（`requiresOnDeviceRecognition: true` を明示的に指定）。
- **実機での動作は未検証です。** Development Buildを作成し、実機で日本語の文字起こしが正しく行われるか必ず確認してください。

### ② ユーザーが後から設定できるサーバーAPI（任意・実装済み）

朝用画面の「文字起こしサーバーAPI設定」から、任意のHTTPSエンドポイントとAPIキー（任意）を設定できます。

- 秘密鍵は**アプリに埋め込まれていません**。すべて端末のセキュアストレージ（`expo-secure-store`）にのみ保存されます。
- 設定しない限り、このプロバイダは「使えない」ものとして扱われ、夜間保存の成功条件には一切影響しません。
- サーバー側は `multipart/form-data`（フィールド名 `audio`）で音声を受け取り、`{ "transcript": "..." }` 形式のJSONを返す実装を用意してください（本リポジトリにサーバー実装は含まれません）。
- ChatGPTの一般的な添付画面が任意の音声ファイルを必ず文字起こしできるとは限らないため、**「ChatGPTを開く」機能は文字起こしの自動化ではなく、あくまで手動でコピー&ペーストするための導線**として実装しています。

### ③ 未処理として保持（フォールバック）

①②のいずれも使えない・失敗した場合、音声は**そのまま**残り、状態は「未処理」（`saved` + `errorMessage: transcription_unavailable`）になります。朝用画面からいつでも再試行できます。**実現できない文字起こしを「動くもの」として偽装していません。**

## 16. 夜間利用の前に、昼間に済ませておく初期設定

1. アプリをインストールし、一度起動する
2. 「夢を録音」ボタンを1回押し、マイク権限を許可する
3. テスト録音を1件行い、朝用画面で再生できることを確認する
4. 設定アプリ → サウンドと触覚 → システムの触覚 がオンになっているか確認する
5. （文字起こしを使う場合）オンデバイス日本語音声認識モデルがダウンロード済みか確認する。またはサーバーAPIを設定する
6. 画面の自動ロック時間を確認する（録音中はKeep Awakeが有効になりますが、念のため「設定 → 画面表示と明るさ → 自動ロック」を長めにしておくと安心です）

## 17. トラブル時に元音声を探す方法

- 朝用画面の「録音一覧」に表示されない場合でも、**音声ファイル自体が自動削除されることはありません**。
- 朝用画面の「復旧候補ファイル（DB未登録）」セクションに、DBレコードと紐づいていない音声ファイルが一覧表示されます（ファイル名・サイズ）。これは起動のたびに自動検査され、**削除はされません**。
- 「処理エラー」セクションには、ファイル欠損・0バイトなどでエラー状態になったレコードが表示されます（レコード自体は削除されません）。
- それでも見つからない場合は、iCloud/iTunesの端末バックアップ、または「13. バックアップ方法」を参照してください。

### 実行結果（このリポジトリでの最終確認時点）

- `npm run typecheck` → エラーなし
- `npm run lint` → エラー・警告なし
- `npm run test` → 8 test suites / 36 tests すべて成功
- `npm run doctor`（`expo-doctor`） → 20項目中18項目パス。残り2項目（Expo設定スキーマの取得・React Native Directoryとの照合）は、**この開発環境がネットワークプロキシ経由でExpoの外部APIへ到達できないこと**が原因の失敗であり、アプリ自体の設定不備ではありません（`npx expo export --platform ios` によるMetroバンドルは1214モジュールすべて解決し成功しています）。実際のネットワーク環境で再実行して確認してください。
- `npx expo export --platform ios` → 成功（iOS向けJSバンドルが正常に生成されることを確認。これは「アプリが依存関係・importエラーなく起動できる」ことの静的な裏付けです）

**注意**: 上記はすべてこの開発マシン(Linuxコンテナ)上での検証です。**iPhone実機での動作確認はしていません。** 実機確認は必ず [19章](#19-手動試験手順実機耐久試験) の手順で行ってください。

## 19. 手動試験手順（実機・耐久試験）

以下はすべて **iPhone実機・Development Build（または本番ビルド）** で行ってください。ブラウザのプレビューやシミュレータでの確認だけでは「実機確認済み」とは言えません。

### 基本動作
1. ホーム画面からアプリを起動する
2. 巨大な赤いボタンを押す → マイク許可ダイアログ（初回のみ）→ 許可 → 短い振動が1回鳴ることを確認
3. 数秒話す
4. 同じボタンを押す → 「保存中…」表示 → 一定間隔で2回の振動 → 「保存しました」が短時間表示され、自動的に元の画面に戻ることを確認
5. 画面上部の「今夜 N件保存済み」が増えていることを確認
6. 日本語のラベル（● 夢を録音／■ 録音を終了／保存中…／保存しました）が文字化けしていないことを確認（スクリーンショットを残す）

### 耐久試験（すべて必須）
7. **3回連続録音**: 3回録音し、朝用画面で3件とも異なる時刻・別ファイルとして残ることを確認
8. **アプリを完全終了して再起動**: タスクスイッチャーからアプリを終了 → 再度起動 → 件数・履歴が保持されていることを確認
9. **iPhoneを再起動**: 端末ごと再起動 → アプリ起動 → 件数・履歴が保持されていることを確認
10. **オフライン録音**: 機内モードで録音・保存し、正常に完了することを確認
11. **録音中に別アプリへ切り替える**: 録音中にホームボタン/スワイプで別アプリを開き、しばらくしてから戻る → 録音が継続しているか、または「中断」として音声が保存されているか（`interrupted`状態）を確認
12. **画面の自動ロック時間を短くして録音**: 設定で自動ロックを最短にし、録音中に画面が暗くならない（Keep Awakeが効いている)ことを確認
13. **電話やアラームによる中断**: 録音中に着信・アラームを発生させ、録音が中断された場合でもそこまでの音声が保存されることを確認
14. **開発サーバーやPCを停止した状態で起動**: PC・Metroサーバーを止めた状態でアプリを単独起動し、録音・保存が問題なく行えることを確認（Development Buildはネイティブ部分が端末に内蔵されているため、JS更新を受け取れないだけで通常動作は可能です）
15. **すべての試験後**: 元音声（再生できること）と件数が、試験前後で減っていないことを確認する

## 20. 既知の制約・実機で未検証の事項

- **本開発環境はLinuxコンテナであり、iPhone実機・iOSシミュレータでの動作確認は一切行っていません。** 型チェック・lint・自動テスト・Metroバンドルの成功のみを確認済みです。
- **バックグラウンド録音**: `UIBackgroundModes: ["audio"]` と `allowsBackgroundRecording` を設定していますが、実機での長時間バックグラウンド録音の安定性は未検証です。Development Buildで実機確認してください。
- **中断検知**: `expo-audio` のJS APIには「中断の開始/終了」を表す専用イベントが無いため、`recordingStatusUpdate` の `hasError`/`mediaServicesDidReset` と、React NativeのAppState変化を組み合わせて中断を推定しています。電話着信等での実際の挙動は実機確認が必要です。
- **オンデバイス日本語文字起こし**: 端末に日本語音声認識モデルがダウンロードされていない場合は失敗します。実機での成功率は未検証です。
- **`expo-speech-recognition` は非公式（コミュニティ製）のExpoモジュール**です。Apple公式のExpoモジュールではありませんが、内部的にはApple公式の`SFSpeechRecognizer`を利用しています。
- **expo-doctor の2項目**（設定スキーマ取得・React Native Directory照合）は、開発環境のネットワーク制限により未確認です。
- Android向けの設定（`app.json`の`android`セクション）も入れていますが、**本要件はiPhone専用のため、Android実機・エミュレータでの確認は行っていません。**
- **アプリアイコン**: 本バージョンでは独自のアプリアイコン画像を用意していません（`app.json`に`icon`等の指定が無いため、Expoの既定アイコンが使われます）。ホーム画面での見た目を仕上げたい場合は、`assets/icon.png`（1024×1024）などを追加し、`app.json`の`icon`/`android.adaptiveIcon.foregroundImage`/`web.favicon`に指定してください。機能には影響しません。
